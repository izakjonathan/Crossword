# v2.11.0 — Seven solving improvements

Baseline: main `6b59113f92c131da687a7ce9471f6c7dc67dfd2f` (discoverable lobbies). All seven additions ship together. Existing solo saves, dated answer history, seven-day shared rooms, round fencing, public UI Studio saves and legacy capability links remain supported.

## Features

1. **Saved games:** open ··· → Saved games. Each visited puzzle is automatically archived with difficulty, filled count, completion state, save date, timing and Solo/Shared label. Filter All/Unfinished/Completed, resume a solo board, join a shared session's current round, or open its saved board as a solo copy. Leave a current shared session before opening another game. Entries are local to this browser, up to 50. Removing an entry removes only the archive copy. Capacity/quota failures are reported; existing entries are not silently evicted. Unknown/corrupt boards are independently validated before restoring. The previous solo session key is retained.
2. **Richer clues:** 62 original tier-2 contextual/alternative-sense clues supplement existing answers. Direct tier-1 wording remains unchanged, so Easy retains its direct-clue policy. Medium/Hard can use the new alternatives within the existing difficulty and crossing requirements. No words, facts, grids or clue text are copied from Vox. No themed-game mode is claimed. See VARIED-CLUES-V2.11.md.
3. **Granular checks:** ··· → Check answers → Letter, Word or Puzzle. Checks inspect entered cells only and do not fill blanks. Preferences optionally highlight errors as you type. Manual checks are shared; automatic highlighting is a personal preference. Check actions are counted when the selected scope contains entered letters.
4. **Timer and summary:** optional timer under the header, plus an automatic completion dialog showing time, hint actions, manual checks and assisted status. Shared timing/counts are server-owned and identical across players. A new round resets them. Completion freezes timing; deleting a correct letter resumes the same clock. Time is elapsed wall time and includes time away/closed tabs. Hosting starts a new shared clock. Hiding the timer is personal and does not pause the game. Older solo saves begin timing when first opened by this build; legacy shared rooms derive their start from original fixed expiry. Counts remain monotonic through undo. View a completed game's summary again from controls.
5. **Responsive clues:** screens at least 1000px wide and 600px tall show scrollable Across and Down clue lists beside the board. Clicking selects the first square and synchronises selection in a shared session. Phone layouts retain the clue strip and keyboard; short landscape retains the board beside the keyboard.
6. **Solving preferences:** timer visibility, automatic checking, stay/next clue at word end, and Space to toggle direction or clear/advance. Settings are device-local. Typing still moves exactly one square through filled crossings; filled-letter skipping remains disabled. Preferences do not change another player's keyboard navigation policy.
7. **Players:** Play together includes an editable 24-character display name and joined-player roster with Connected/Away. An authenticated-by-membership heartbeat refreshes about every ten seconds. A player is Away after 35 seconds without heartbeat, observed at the next refresh. This is approximate presence, not instant disconnect detection. The status strip retains this device's saving/reconnecting/generation status and shows online count. Closing a tab marks the device away later but does not leave membership; explicit Leave still affects only that device.

## Persistence and compatibility

New device-local keys: `daily-cross:library:v1` and `daily-cross:preferences:v1`. Solo session stats are optional additive data; old saves load without resetting answers or history. Server room `stats` and lobby `:profiles` hash are additive. Lua updates metrics and completion alongside the existing edit/lease transaction; deduplication prevents retry double-counts. Profile TTL matches lobby lifetime, explicit leave removes its profile, and final leave deletes the profile hash. Only joined members can heartbeat/read names; public lobby discovery still excludes tokens and player identities. No credentials are sent to clients. Old clients can still edit existing rooms; reload both devices to use new dialogs and stats.

The library caches independently validated archive data and avoids resaving unchanged polling snapshots. Before new puzzles/opening saved games, the current board is archived. Shared observers archive their prior round before rebinding to the next puzzle. Library failures are surfaced without modifying the repetition ledger. Existing stored clues remain as originally saved.

## Verification

Use `npm test` with a disposable Redis instance, `npm run build`, `LAYOUT_BUILD=1 node --test tests/layout.test.mjs` and `npm run audit:puzzles`. The final evidence is recorded in docs/testing.md. Historical deterministic fixtures remain; a new v2.11 fixture freezes the intentionally revised clue outputs. There are no dependency changes and no configured lint/typecheck scripts.

Physical iPhone gestures, VoiceOver and broad human difficulty calibration are not certified by automated tests. Presence relies on browser scheduling and network connectivity. This app still generates original quick-definition crosswords; it does not claim newspaper editorial quality or cryptic wordplay.

## Production storage correction

Upstash's Lua JSON encoder can drop null array elements and collapse blocked grid positions. The server now reconstructs exact positions from the existing validated entries, writes false sentinels for blocked squares inside Redis, and restores nulls at the API boundary with independent validation. Existing collapsed room grids recover without deleting answers, memberships, revisions or history. Optional null completion timestamps are normalised too. No publisher content or gameplay rules change. All 112 tests with real Redis and the production build/CSS checks pass after this correction.

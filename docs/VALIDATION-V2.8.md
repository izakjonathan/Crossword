## Browser verification

Production Chromium, mobile 390×844 and landscape 844×390: restore a genuine puzzle generated by the unmodified v2.7 source with an entered letter; type, browse Across/Down clues, select clues, reveal a letter, clear/undo, preview/cancel/save UI Studio colours, reload progress and palette, rotate, and generate each new difficulty. Check worker response ratings and the actual stored puzzle, no repeated answers across the sequence, no horizontal overflow, dialog focus/inert behaviour and first-load recovery after a synthetic corrupt ledger.

No server/database/API credentials are part of the solve path: the application shell loads, a browser Web Worker fills the bank, the locked local ledger commits and the board renders the saved result. Targeted browser checks are performed in disposable test contexts, not a real user's storage.

## Limits

Real iPhone Safari chrome tint and touch/VoiceOver behaviour remain unverified here. Automated tests do not certify every clue's meaning, the uniqueness of every natural-language solution, or solve-time ordering for every person. Vocabulary and clue bands are editorial starting points; wider human test-solving remains necessary. The finite bank and strict repeat ledger can still exhaust a difficulty; the app retains the current puzzle rather than weakening those rules.
